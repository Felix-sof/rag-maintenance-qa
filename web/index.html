Architecture

How it works

A retrieval-augmented assistant that can also call tools: the documented failure rules, and SQL over the recorded processes. Each claim below is measured; the evaluations are in the repository.

0.942retrieval MRR on hard questions, hybrid + rerank (vectors alone: 0.786)
308 / 308HDF, PWF and OSF labels reproduced by the documented rules, 0 false alarms
0 / 75in-scope questions wrongly refused by the off-topic gate
≤ 2model rounds per answer, tool calls included (a follow-up adds one to rewrite it)
1

Retrieve

Dense vectors (multilingual-e5) and BM25, fused with Reciprocal Rank Fusion and re-ranked by a cross-encoder. The index lives in PostgreSQL with pgvector.

2

Gate

A question whose best match is too weak is refused before any LLM call. Questions with sensor readings go to the tools instead.

3

Reason with tools

Through Gemini function calling, the model can apply the failure rules to the given readings, find the most similar recorded processes with pgvector, or run a fixed SQL query. It never writes SQL itself.

4

Verify

Each answer cites passages as [n] and tool results as [T1]. Every number in it is checked against the cited sources, and conflicting documents are flagged rather than silently resolved.

The reference documents and the 10,000 recorded processes come from the AI4I 2020 Predictive Maintenance Dataset (S. Matzka, CC BY 4.0), which is synthetic. The procedure documents are illustrative, not a manufacturer's manual.
